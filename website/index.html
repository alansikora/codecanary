The loop

Push once. Review, fix and re-review run without you.

With fix.enabled, a review that leaves findings open is followed by a fix job in the same workflow. Scroll through one pull request.

  1. 01

    You push

    The CodeCanary workflow runs on every push to a pull request, from GitHub Actions. Drafts are skipped. Prefer one review per PR? Set review_on: ready.

  2. 02

    Your model reviews the diff

    It reads the diff, the files around it, your CLAUDE.md and the .claude/rules that match the changed paths. Findings land inline on the exact diff lines, each with a severity.

  3. 03

    Claude fixes it in CI

    The fix job runs Claude on the PR branch. Each finding is applied with a minimal edit, or refuted with a reply on its thread when it doesn't hold for your repo. Tools: Read, Grep, Glob, Edit, Write. No Bash, no network.

  4. 04

    One commit, pushed

    One commit, authored as the PR author and co-authored by Claude, with a CodeCanary-Fix trailer. It's pushed with the app token, so CI and the next review run on it.

  5. 05

    Triage, then re-review

    A Go classifier sorts the open threads before any model runs. Threads with no code change and no reply are skipped at zero LLM cost; the rest are re-checked in parallel by the triage model. Only the new diff gets a full review.

  6. 06

    Threads resolve. Merge.

    Threads whose code was fixed resolve themselves. With nothing at warning or above left open, the CodeCanary / review status turns green. Make it a required check and it gates the merge.

Bounded by design. At most 2 fix commits since your last push and 5 per PR, by default. At a limit it stops and comments with the findings still open.

Loop limits

fix.max_per_push (default 2) and fix.max_per_pr (default 5), counted from commit trailers. Your own push resets the per-push count.

Same-repo PRs only

The fix never runs on fork PRs or drafts, and does nothing if the head moved past the reviewed commit.

Confined edits

Read, Grep, Glob, Edit and Write only. .github/, .codecanary/ and .claude/ are never changed; Go reverts any edit there.

Never red

If the fix can't run (rate limit, provider error), it comments once and leaves CI green. Pick it up locally with /codecanary-fix.

Requires provider: claude, review_on: push and workflow template v3 (codecanary setup github).

Local

Same engine, before you push.

codecanary review diffs your branch, uncommitted changes included, against the default branch and prints findings in your terminal. Nothing is fetched from or posted to GitHub.

  • Incremental re-runs. State is kept per repo and branch under ~/.codecanary, so the second run triages what the first one found.
  • Post when ready. --post reviews the PR and posts the findings to it on GitHub.
  • Sign off without a workflow. codecanary signoff posts the CodeCanary / review status from a clean local review.
  • Scriptable. --output json for tooling, --dry-run to see the prompt without calling a model.

Claude Code

Say “handle codecanary”. Walk away.

The bundled codecanary-fix skill drives review → triage → fix until the PR is clean. It judges each finding against your project's conventions on its own: legitimate ones are applied, wrong ones are refuted. No per-finding approval prompts.

pr-loop

PR with the workflow. Fix, commit and push each cycle; with fix_on_ci it waits for the bot's fix commits and takes over when the bot stops.

local-loop-git

PR without a workflow. Local reviews, a commit per cycle, and an offer to push at the end.

local-loop-nogit

No PR. Local reviews, fixes applied in place, no git.

  • Skips are explained. In pr-loop, every skipped finding gets a reply on its review thread with the reason.
  • Understands review_on: ready. Each cycle moves the PR to draft, pushes one commit, waits for required checks, and marks it ready again.

Under the hood

A reviewer that remembers what it already said.

Incremental triage

On re-push, a Go classifier sorts every open thread before any model call. Unchanged threads cost nothing; changed ones are evaluated in parallel with the cheaper triage model; the review covers only new code.

[skip]no code change, no reply0 LLM calls
[evaluate]code changed or author repliedtriage model
[resolved]fixed by code changeauto

Conversational

Reply to a finding and it's re-evaluated in context. It tells a code fix from a dismissal, an acknowledgment or a rebuttal.

Merge gate

Every review posts a CodeCanary / review commit status. Warnings and above fail it; suggestions and nitpicks don't.

Anti-hallucination

An explicit file allowlist, line validation against the diff and a distance threshold keep findings on real code.

Review once, at ready

review_on: ready reviews when a PR opens or turns ready and skips pushes after that. Iterate in draft for free.

Your conventions, scoped

Project CLAUDE.md files and .claude/rules/*.md feed the review. A rule with paths frontmatter is included only when a changed file matches it, so reviewers see the rules that apply.

Costs you can see

A fast model for triage, a full model for review, and a per-invocation usage table on every run. Cap a review with max_budget_usd.
